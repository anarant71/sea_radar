## Запуск


## Что сделано

- `src/server/toVessel.ts` — преобразование одного сообщения `PositionReport` в судно. Написано по сохранённому образцу: координаты берутся из `Message.PositionReport.Latitude/Longitude` (полная точность), а не из округлённых до пяти знаков `MetaData.latitude/longitude`.
- Вход преобразователя — `unknown`: ни одно поле не считается существующим, пока не проверено. Негодное сообщение возвращает `null`, судно с координатами 0,0 не появляется.
- `time_utc` разбирается шаблоном под Go-рендер времени (пробел вместо `T`, смещение без двоеточия, зона в конце). Дробная часть переменной длины, наносекунды обрезаются до миллисекунд, а не округляются.
- MMSI приходит числом и переводится в строку; `ShipName` добит пробелами до двадцати символов, края обрезаются, пустое имя — `null` через общую с демонстрацией `toVesselName`.
- Валидация по SPRINT-02: широта вне [-90, 90], долгота вне [-180, 180], непарсящееся время и пустой MMSI отбрасывают позицию. Скорость вне [0, 102.2] и курс вне [0, 360) дают `null`, позиция при этом принимается.
- `collectSnapshot` в `src/server/reader.ts` — накопление набора на месте прежнего чтения одного сообщения. Соединение и часы остались параметрами, сетевого кода и вызовов `Date` модуль по-прежнему не содержит.
- Набор — `Map` по `id`: одна позиция на судно, самая новая по `time_utc`, при равных метках остаётся принятая первой. Новое сообщение заменяет объект судна целиком.
- Предел `SNAPSHOT_VESSEL_LIMIT` = 100 в `src/config.ts` считается по числу судов, а не сообщений; при достижении сбор завершается немедленно.
- Частичный набор после ошибки, разрыва и отмены не отдаётся: успех уходит только из `succeed`, остальные исходы — через `fail` с кодом.
- Результат завершается один раз: единственная функция завершения снимает таймер, отписывается от `abort` и закрывает соединение.
- `GET /api/snapshot` отдаёт полную форму ответа: `{ ok, vessels, collectedAt, windowSeconds, count, truncated, reason }`; ошибки — прежние HTTP 502 и пять кодов из `src/server/snapshotError.ts`.
- `src/snapshot.ts` — разбор ответа и тексты панели литералами: кнопка, подписи четырёх состояний, сообщения пустого ответа и ошибки. Числа в подписи берутся из ответа и конфигурации, а не пишутся в строку.
- `RadarView` держит одно состояние экрана (`idle-demo` / `loading` / `loaded` / `error`) вместо набора флагов; показан результат последней попытки и никакой другой.
- Демонстрационный таймер останавливается при нажатии кнопки; суда, выбор и карточка убираются в момент нажатия, до ответа сервера.
- Набор прошлой попытки не сохраняется ни при ошибке, ни при пустом ответе — состояние заменяется целиком.
- Возврат карты к начальному виду — только на первом непустом успехе, дальше вид не трогается.
- Значки, карточка и структура `Vessel` переиспользованы без изменений: `VesselCard.tsx` и `vessel.ts` не менялись.
